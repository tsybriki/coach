# 07 · Реализация

План работ. Сначала база, чтобы приложение открылось и показало неделю; потом остальное.

## Правила

Стандарт `development-standards`: слои `domain → ports → app → adapters`, зависимости строго
вниз, тест на каждый доменный инвариант, доступ к данным только через порты,
деградация вместо отказа.

Конституция проекта — `.hermes.md` в корне нового репозитория. Каждое правило с проверяющей
командой.

## Этап 0 · Репозиторий и каркас

- Новый репозиторий `coach-app` (не в `~/coach` — пайплайн не трогаем).
- `.hermes.md` — конституция.
- `pyproject.toml`, `pytest`, `ruff`, `mypy`.
- Пустая структура `app/{domain,ports,services,adapters,api}` + `tests/`.
- `tools/check_storage_leaks.py` — перенос чекера из `~/coach/v2.architecture/`.
- CI: тесты зелёные **и** чекер утечек зелёный — обязательное условие коммита.

**Готово, когда:** `pytest` проходит на пустом домене, структура соответствует `.hermes.md`.

## Этап 1 · Домен

Перенос 18 сущностей и 43 инварианта из `DOMAIN-SPEC.html` в код.

- `app/domain/` — по модулю на агрегат: `season.py`, `week.py`, `workout.py`, `actual.py`,
  `summary.py`, `slots.py`, `command.py`.
- Каждый инвариант — тест. Имена тестов = номера инвариантов (`test_i09_link_is_bidirectional`),
  чтобы связь со спецификацией не терялась.
- Производные значения — функции, не поля.
- `tests/unit/` — домен без I/O.

**Готово, когда:** 43 теста инвариантов зелёные, `mypy` чистый.

## Этап 2 · Хранилище

- `app/ports/storage.py` — пять интерфейсов: `SeasonRepo`, `FactRepo`, `AthleteRepo`,
  `MethodologyRepo`, `CommandLog`.
- `app/adapters/storage/files.py` — реализация поверх файлов.
- Версия схемы + `migrations/`.
- `tools/import_coach_state.py` — импорт из `~/coach/state`, отчёт о расхождениях.
- `test_contract_*_repo.py` — один набор тестов на все порты хранения.

**Готово, когда:** импорт `~/coach/state` даёт рабочее состояние, контрактные тесты
зелёные, `tools/check_storage_leaks.py` не находит утечек.

## Этап 2б · Переход на базу данных

Спланирован заранее, выполняется по триггерам из `02-хранилище.md`.

- `app/adapters/storage/sqlite.py` — вторая реализация тех же портов.
- Схема в SQL — по домену, без JSON-в-колонке.
- `tools/migrate_to_db.py` — перенос данных через порты, со сверкой.
- Переключение — конфигом, оба адаптера живут одновременно.

**Готово, когда:** одни и те же контрактные тесты зелёные для обоих адаптеров,
перенос сверен, а SQLite-адаптер проверен на реальном сезоне.

## Этап 3 · Сервисы

- `app/services/planner.py` — вход 2: макро + неделя → тренировки.
- `app/services/goal_feasibility.py` — вход 1: вердикт по достижимости + варианты.
- `app/services/assessment.py` — связывание, вердикты, саммари.
- `app/services/replanner.py` — вход 3: переплан остатка.
- `app/services/methodology.py` — слой «правила + исполнитель»: данные правил и код их
  применения разделены, но оба — часть методологии.

**Готово, когда:** на реальном сезоне 2026–27 планировщик воспроизводит неделю,
не хуже текущего `plan_generate.py`.

## Этап 4 · BFF

- `app/api/` — роуты по `03-BFF.md`, схемы ответов, токен.
- ETag по версии, SSE `/events`.
- Деградация: Garmin, календарь, нарратор.

**Готово, когда:** `curl` с токеном отдаёт неделю, команда возвращает diff,
испорченный Garmin не роняет `/health`.

## Этап 5 · Клиент

- PWA по `05-клиент.md`: неделя, детали, сезон, план против факта, связывание, закрытие.
- Offline: снапшот в IndexedDB, outbox, service worker.
- SSE-подписка с backoff.

**Готово, когда:** приложение ставится на телефон, открывается без сети и показывает
последнюю неделю; команда в офлайне уходит после появления сети.

## Этап 6 · Хостинг

- `cloudflared` в `systemd --user`, BFF в `systemd --user`.
- Домен, сертификат, токен.
- Бэкап хранилища по расписанию (реализация — в адаптере).

**Готово, когда:** с мобильного интернета открывается неделя; из дома — напрямую.

## Что сознательно не входит в базу

| Не делаем | Почему |
|---|---|
| Регистрация, роли, восстановление пароля | Один пользователь |
| Push-уведомления | Не запрошены; SSE достаточно |
| Несколько сезонов одновременно | Домен: один активный план |
| Синхронизация между устройствами | Один сервер — один источник правды |
| Импорт/экспорт произвольных форматов | Только свой формат + импорт из пайплайна |
| Логирование в облако | Данные дома |

## Порядок и зависимости

```
0 → 1 → 2 → 3 → 4 → 5 → 6
        ↑         ↑
    импорт   план+факт
```

Этапы 1 и 2 независимы от 3–6. Этап 5 (клиент) можно вести параллельно с 3–4: клиент
работает против заглушки API, которая отдаёт снапшот из хранилища.
