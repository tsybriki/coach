# v2.architecture

Рабочая папка для **новой архитектуры Coach App** (приложение-тренер).

Сегодня (26.10.2026) здесь лежит **операционная доменная модель** — та часть, что описывает
внутренний контур: сезон, план, неделя, тренировка, шаг, слоты, связывание плана с фактом —
и **логический уровень архитектуры**: кто какое решение принимает.

## Что здесь

| Файл | Что это |
|---|---|
| `DOMAIN-MODEL.md` | Операционная доменная модель: 18 сущностей, 43 инварианта, 6 открытых вопросов |
| `LOGICAL.html` | Логические подсистемы: 8 подсистем, 15 взаимодействий, 3 развилки |
| `design/` | Дизайн остальных уровней — **9 отдельных файлов** (см. `design/00-index.md`) |
| `DESIGN.html` | Сборка девяти файлов дизайна в один документ (рендер из `design/*.md`) |
| `SUBSYSTEMS.html` | Смешанная логика+физика версия — **заменена логической**, лежит для истории |
| `README.md` | Этот файл — навигация по папке и по тому, что впереди |

## Уровни абстракции

1. **Логический** — кто какое решение принимает. Проработан: `LOGICAL.html`.
2. **Контрактный** — как подсистемы общаются (данные, команды, порты). Проработан:
   `design/01-контракты.md`.
3. **Физический** — где это живёт и как хранится. Проработан: `design/02`…`06`.

Доменная модель (`DOMAIN-SPEC.html`) — **источник правды** для операционного контура.
Логический уровень — поверх него: домен отвечает «что за сущности», логический уровень — «кто что решает».

## Как с этим работать

**Источник правды — HTML:** `~/projects/coach-app/DOMAIN-SPEC.html`.
Он рисуется, в нём видно диаграмму и подтверждённые инварианты. Правки вносятся туда,
`DOMAIN-MODEL.md` пересобирается синхронно (скрипт конвертации — в этом же репо, см. ниже).

**Формат работы с моделью** (зафиксирован Кириллом):

1. Модель в четырёх блоках: диаграмма → сущности → связи → вопросы.
2. Кирилл читает инварианты по одному и подтверждает. Подтверждённые помечаются в HTML
   зелёной галочкой, дублируются в списке «Подтверждённые инварианты» и прогресс-баре.
3. Ответы на вопросы фиксируются в таблице «Решения по вопросам» — они действуют как правила модели.
4. Ничего не инициируется само: любое изменение состояния — через `Command`, инициированный пользователем.

## Что не сделано

Операционная часть закрыта. Впереди:

- **Реализация** — домен в код, слои domain/ports/app/adapters, тест на каждый инвариант.
- **Методология нагрузки** — задача [#6](https://github.com/tsybriki/coach/issues/6): считаем
  intensity minutes сами, с учётом зон атлета. Референс: [TSS Explained](https://share.google/JlFPisYIM7Fczte8R).
- **Хранение** — формат, объём, атомарная запись, миграции схемы.
- **Адаптеры** — Garmin (интенсивность по тренировкам), Stryd, календарь.
- **UI** — неделя, детали сессии, сезон, план vs факт, ручное связывание, закрытие недели.
- **Синхронизация** — mobile + offline: снапшот в IndexedDB, outbox команд.
- **Оценка формы** — как измерять результат работы мозга.
